# Single-Source the Mascot Placement Rules

**Date:** August 25, 2026
**Project:** ibook-skills/skills/book-installer
**Commit:** `16c76971` (shared with the skill-versioning change — see
[`consistent-skill-versioning.md`](consistent-skill-versioning.md))

## Summary

The rules governing when a learning mascot may appear, how often, and which pose
carries which pedagogical job had been retyped into five skill files plus every
generated book. The copies had already drifted apart. This session extracted them
into one canonical file, converted every other mention into a reference, and added
a renderer plus a checker so the single-source property is mechanically enforced
rather than merely intended.

## Problem Statement

The session began as a read-only question: "there are now multiple places that
describe when to use mascots — find the most detailed one." Scanning every
markdown file in `skills/` turned up nine locations, and comparing them revealed
they were no longer saying the same thing.

The most detailed guidance was the **"Mascot Admonition Guidelines (Instructional
Design Rules)"** section of `learning-mascot.md`, added three days earlier on
2026-08-22 in commit `15a18137`. It gives each of the seven poses an
*instructional purpose / rule / tone* triple grounded in named instructional-design
frameworks (WIIFM, advance organizer, cognitive scaffolding, anticipatory
guidance, ARCS satisfaction). Nothing else in the repo came close.

Three concrete drifts had already appeared between the copies:

| Drift | Where | Consequence |
|-------|-------|-------------|
| `mascot-encouraging` vs `mascot-encourage` | `mascot-chapter-updater.md:53` | `mascot.css` defines only `mascot-encourage`, so following the updater guide produced an **unstyled admonition that still passed validation** |
| `mascot-thinking` "2-3 per chapter" vs "1–3" | `learning-mascot.md` vs `mascot-chapter-updater.md` | Two placement tables disagreeing on the same number |
| Markdown-vs-HTML image path rules | Present only in this repo's `CONTENT-GENERATION-GUIDE.md`, absent from the template | Every *other* book generated so far lacked the rule that prevents a `mkdocs build --strict` failure |

Worse, `validate-chapter-mascots.py` accepted both class names and labelled
`mascot-encourage` the *"legacy name"* — exactly backwards from the CSS.

## The Constraint That Shaped the Design

"Single location" could not mean "one file, zero copies," because the rules have
**two audiences**:

- **Authoring time** — agents running skills inside `ibook-skills`, which can read
  any file in the repo. These can use a reference.
- **Generation time** — agents writing chapters inside a *book repo*, a separate
  deliverable that must stand alone. These need a physical copy.

So the design separates *one authored source* from *mechanically rendered copies
that no one hand-edits*. The existing copies were retyped prose, which is precisely
why they drifted; a copy produced by a script cannot drift by paraphrase.

## Design Decisions

### Canonical location: inside the skill that owns the feature

`skills/book-installer/references/mascot-placement-rules.md`

This follows the precedent already set by
`chapter-content-generator/references/blooms-taxonomy.md` — a canonical reference
living inside the owning skill, cited by three other skills. A new
`skills/_shared/` directory was rejected: `bk-install-skills` symlinks *every*
directory under `skills/`, so it would need an installer skip-list change and
would surface as a phantom skill.

### Reference form: `$BK_HOME`, not `~/.claude/skills/`

The first proposal used `$HOME/.claude/skills/...`, copying the Bloom's precedent.
**That was wrong**, and the user caught it. Skills install to three different
locations depending on framework:

| Framework | Install path | Installer |
|-----------|--------------|-----------|
| Claude Code | `~/.claude/skills/` | `bk-install-skills` |
| OpenAI Codex | `~/.codex/skills/` | `bk-install-skills-codex` |
| Google Antigravity | `~/.gemini/antigravity/skills/` | `bk-install-skills-antigravity` |

A path hardcoded to any one of them resolves on one framework in three. `$BK_HOME`
points at the repo regardless — and `cover-image-generator.md:59-61` already said
so explicitly. The canonical file documents the fallback for when `$BK_HOME` is unset.

*(The pre-existing `blooms-taxonomy.md` references have this same bug. Filed
separately rather than mixed into this commit.)*

### Rendered copies live between sentinels

`render-mascot-guide.py` reads the canonical file, substitutes character values
from `docs/img/mascot/character-sheet.md`, demotes headings one level, and splices
the result between:

```
<!-- BEGIN mascot-placement-rules — generated by render-mascot-guide.py; do not edit by hand -->
<!-- END mascot-placement-rules -->
```

Re-running replaces **only** what sits between the sentinels. The per-book Mascot
File Index, Character Overview, and Voice Characteristics are authored above them
and survive every re-render. This structure was a mid-session correction: the first
version emitted the `## Learning Mascot` heading *inside* the block, which would
have wiped the book-specific content on the second run.

`--check` exits non-zero if the block was hand-edited; `--stdout` prints without
writing.

### A checker, because intent is not enforcement

`scripts/bk-check-mascot-rules` greps `skills/` for restated placement tables,
per-chapter counts, and the wrong class name, and verifies rendered blocks still
match. Without it the rules re-scatter within months — that is how they got here.
It found its first violation immediately: a changelog line in this very session's
own `book-installer/SKILL.md` edit, which had to be reworded.

`instructors-guide.md` is exempt and marked *derived*: it is teacher-facing prose
in a generated deliverable and cannot be a pointer.

## Relaxed Limit

At the user's direction the per-chapter ceiling rose from **6 to fewer than 10**
(9 enforced), appropriate for longer chapters. The rules state the cap is a
consequence of a chapter having that many genuine signal-worthy moments, never a
target to fill; short chapters should sit nearer 4–5. All 35 chapter files in this
repo pass at the new ceiling.

## Bugs Found and Fixed Along the Way

1. **`mascot-encouraging`** — undefined in `mascot.css`, rendered unstyled, passed
   validation. Now reported as a fixable warning, with the validator's backwards
   "legacy name" comment corrected.
2. **Chapter 1 self-introduction vs the sentence cap** — the validator flagged
   chapter 01 at 18 sentences against a 1–3 cap that the rules *explicitly exempt*
   it from. The validator was contradicting the rules it existed to enforce. Now
   detects the pose-enumeration list and skips the cap.
3. **Nested `-->`** — a note written into the init-textbook base template quoted
   the sentinel syntax literally inside an HTML comment, which would have closed
   the comment early and spilled text onto the rendered page. Caught before commit.

## Verification

```bash
./scripts/bk-check-mascot-rules                                    # zero restatements
python3 skills/book-installer/scripts/render-mascot-guide.py --check # no drift
for c in docs/chapters/*/index.md; do \
  python3 skills/book-installer/scripts/validate-chapter-mascots.py "$c"; done
```

Render idempotency was confirmed (second run is a no-op) and drift detection was
tested by deliberately tampering with the rendered block.

## Key Takeaways for Future Sessions

- **Duplication that a human maintains will drift; duplication a script maintains
  will not.** The fix was not "delete the copies" — one copy is structurally
  required — but "make the required copy generated."
- **Check the reference form against every install path, not just Claude's.** The
  `~/.claude/skills/` habit is easy to repeat from existing precedent and silently
  breaks two of three supported frameworks. `$BK_HOME` is the portable form.
- **A validator that disagrees with its own specification is worse than none.**
  Two of the three bugs here were the checker and the rules contradicting each other.
- **Write the drift guard in the same session as the extraction.** It caught a
  violation introduced by that very session's own edits.
